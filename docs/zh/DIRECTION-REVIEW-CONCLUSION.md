## 1. 一致通过的判断（无分歧）

1. **方向反转本身是对的**：放弃"给 Claude/Codex/OpenCode/Pi 装适配器"，拥抱 AGENTS.md 生态（Linux 基金会托管、24+ 工具原生读取）。这是全篇最重要的判断。

3. **drift 降级**：从"核心差异化/独立 M2 引擎"降级为 `evokit compile --check`（CI exit code + 外部 state.json 存 hash），**产物不注入 HTML 注释标记**。
4. **prune 移出独立里程碑**：降级为 compile 时的 token 预算告警。
5. **编译焦点转移**：从 always 层双目标（AGENTS.md↔CLAUDE.md）转移到 scoped/on-demand 层（.mdc / SKILL.md 是 AGENTS.md 的能力缺口）。

## 3. 核心机制（双向 promote + 上下文健康）

### 3.1 双向 promote（同步）

原蓝图是"单向编译"，MiMo 指出真实场景是**双向编辑**——agent 自己会改 CLAUDE.md/AGENTS.md。修正为：

- 主循环：监测产物侧改动（含 agent 写入）→ 提示 promote 回流 canonical → 重新编译分发
- drift 降级为 promote 流程里的比对步骤

**约束（Kimi + GLM 的硬性要求）**：

- 默认严格**单向**（canonical → 产物）；反向操作是**独立的、显式标记危险的命令**（如 `evokit absorb`），不走默认路径
- 反向回流必须**人工逐条确认**，禁止批量自动
- "双向同步"措辞危险，对外叙事避免使用（会被读成"又发明了双向同步难题"）

### 3.2 上下文健康（doctor 重写版）

原地作用于现有 AGENTS.md/CLAUDE.md，**不以 canonical 编译为前提**，直接命中真实痛点：

- prune：裁剪"可推导事实"（目录布局/依赖表/复述 linter 的规则）
- token 预算：每次会话白付多少 token
- 敏感信息扫描：agent 往 AGENTS.md 写密钥是已有报道的事故
- 过期检测：stale 指令主动误导

**prune 的关键约束（MiMo + Hy4）**：启发式必须区分"可推导事实"（可删）与"指令/约定/坑"（模型推不出来的因果，不能裁，否则裁掉人写 +2.4% 的价值）。prune 可行性验证单独立项，不拍脑袋。

## 4. 三项自有资产（替代"推理链唯一"）

| # | 资产            | 性质  | 说明                                     |
| - | ------------- | --- | -------------------------------------- |
| ① | 上下文健康引擎       | 算法型 | prune/审计/token/staleness + dedup 归一化指纹 |
| ② | 双向 promote 同步 | 机制型 | 产物侧改动回流 canonical 再分发（实验性，见下）          |
| ③ | 架构决策推理链       | 内容型 | "决策为什么 + 影响范围"，AI 推不出来的因果              |

**两条硬性执行注记（GLM）**：

- 资产②风险最高，需先定义 **ownership 规则**（EvoKit vs Claude memory 谁是 writer of record）；规则未定义前标为"实验性资产"，非承诺交付项。
- 资产③编译进目标时**必须带 `shareable` 隐私门控（默认 false）**——memory 层含本地性内容，逐条编译可能泄漏进 git 团队仓库。

## 7. 单目标 vs 多目标的裁决（Hy4 补充）

多目标编译的正当性**不依赖"AGENTS.md 统一"**（那会自相矛盾），而建立在**补齐 AGENTS.md 的能力缺口**上：

- AGENTS.md 覆盖常驻层（always）→ 统一部分，多目标无必要
- scoped（globs 路径规则）和 on-demand（SKILL.md 按需触发）是 AGENTS.md **没有**的机制 → 这才是多目标的正当理由

M1 只做 AGENTS.md 单目标，其余留到验证之后。

---

## 8. 冷启动与候选落盘的边界（Hy4 + Kimi）

- 冷启动草稿输入源必须纳入 v1 已有资产：`.evokit/knowledge-index.md` 和 `template/` 四套模板，顺带兑现"一次性迁移"承诺
- AI 候选**只能写入待确认区（`.evokit/candidates/`），绝不能直接写进 `always/`**——否则"降级"变回自动入库
- 草稿显式标记 `status: draft`，人工确认前不进入任何编译产物

---

## 9. MiMo 三条落地备忘（采纳）

1. **需求验证必须前置，且 promote 本身也是未验证假设**：doctor 零门槛、可先发探真实需求；promote 待验证通过后再重投入。不要在 M0 写码前跳过"3-5 个真实多工具团队访谈 + rulesync/Ruler 正面对比表"。
2. **doctor 与 promote 是两层价值，交付分层**：doctor 不以 canonical 为前提（零门槛获客层）；promote 必须有 canonical（深度工作流层）。**doctor 先行、promote 跟进**，避免为了 promote 先建整套 canonical schema 却没人用。
3. **promote 弃用 HTML 边界标记**：改用段落级规范化指纹对齐（复用 dedup.ts 归一化逻辑）或全文件段落对齐；scoped/promote 需兼容 monorepo 嵌套 AGENTS.md"近者优先"语义。
