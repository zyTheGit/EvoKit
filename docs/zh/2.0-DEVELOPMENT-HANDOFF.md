## 三、未完成事项

### 3.1 分支未推送到远程

`feature/2.0` 分支目前**仅存在于本地**，尚未 push 到远程。后续需执行：

```bash

```

### 3.2 claude agent 超时未解决（第三方 bug）

**现象**：`inventory --agent claude` 超时（120s 无返回）。

**根因**：用户 `~/.claude/settings.json` 将模型锁定为 StepFun 的 `step-5-preview`，claude 2.1.302 无法识别该模型（`unrecognized_model`），长 prompt（约 8KB）触发流式解析死锁。短 prompt 能正常返回，长 prompt 必卡。

**归属**：claude 2.1.302 + step-5-preview 组合 bug，EvoKit 侧无法根治。

**解决方向**（待用户决策）：
1. 临时切回 claude 官方模型跑 inventory，跑完再改回 StepFun 配置；
2. 等待 claude 版本更新，正式识别 step-5-preview；
3. 改用 codex 或 pi 做日常冗余体检（这两个已可用）。

### 3.3 pi 默认 provider key 过期（已规避，未根治）

**现象**：pi 默认 provider `opencode-go` 的 API key 已过期（`401 api_key_expired`）。

**已规避**：EvoKit 的 pi 配置已指定 `model: deepseek/deepseek-v4-pro`，绕过过期 key。

**未根治**：需用户重新登录 pi 或更换 opencode-go 的 key。若后续要恢复使用 opencode-go 模型，需先处理 key 过期问题。

### 3.4 报告质量未全面验证

codex/pi 的 6 区块静态冗余审计报告**已实测跑通**，但未在真实、完整、多样的知识库上做质量评估。建议后续：

- 在不同规模、不同结构的项目上验证报告质量；
- 核对 6 区块（审计范围/重复项/冲突项/过期断链/可清理缓存/整理建议）是否都完整产出；
- 验证「保守原则」是否被 agent 遵守（不凭同名/体积大/时间久就下结论）。

## 四、遗留问题（已知，非阻塞）

### 4.1 `--output` + `--project` 同时出现的优先级

当前 `--output` 绝对优先，且不创建项目 reports 目录。行为已明确，但建议在文档中显式说明，避免用户困惑。

### 4.2 codex 需在受信 git 目录运行

codex 在非 git 目录运行 `inventory --agent codex` 会报「Not inside a trusted directory」。这是 codex 自身约束，EvoKit 已完整回显 stderr 让用户可见，但未做前置检查。可考虑在调用前检测是否在 git 目录，给出更友好的提示。

### 4.3 交接文档待补 debug 配置章节

`docs/zh/INVENTORY-CLAUDE-TIMEOUT-HANDOFF.md`（在 feature/2.0 分支中）已记录超时排查结论，但尚未补「统一 debug 配置」章节。debug 系统的三种启用方式（`--debug` / `EVOKIT_DEBUG` / `settings.debug`）应补充说明。
