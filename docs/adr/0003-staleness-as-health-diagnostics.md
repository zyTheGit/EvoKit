# ADR 0003 — 过期检测不做时间衰减，收敛为"健康诊断 + 复审调度"

## 状态

已接受（本轮 grilling 会话）

## 背景

ADR 0002 把 `confidence` 定义为"维护/新鲜度信号"，并给出离散三档状态机（0.9 FRESH → 0.5 STALE → 0.1 RETIRED），但降档触发**完全依赖"AI 在对话中意识到失效"**：状态机、`expire()`、`collectStale()` 都已实现，却没有任何自动信号把条目推进 STALE，也没有健康指标或复审调度。这条"时间轴"只有两端（崭新/发霉）没有"谁来驱动"。

## 决策

降档仍由**人工/AI 二分判断**驱动（时间流逝不自动衰减，与 ADR 0002 一致），但新增一个**知识库健康诊断层**，让系统主动"表面化"该被复审的条目：

1. **知识库健康诊断**（`evokit doctor` / `evokit boot`）：双向索引漂移（`knowledge/` ↔ `knowledge-index.md` 孤儿）、frontmatter 合法性、`.pending/` 积压、STALE/RETIRED 积压、条目分布（by scope/type/confidence）。
2. **复审调度**：`evokit review` 待复审名单在 confidence 升序（RETIRED 最可疑在前，已实现）基础上，同档内按 `updated` 升序（"先看最久未复审的"）——是**优先级提示**，不是自动降档。
3. **索引重建时机**：索引是派生物，写路径即时重建（已实现）+ boot/doctor 漂移检测 + `--fix` 重建；不做定时/轮询重建。

## 取舍

### 选择"健康诊断表面化"而非"自动降档"

- **放弃**：全自动过期检测的省心度（条目自动过期、自动进复审）
- **获得**：二分判断哲学不变、"人工背书唯一闸门"不破、无噪声误报复审
- **代价**：降档仍需人/AI 点一下，系统只负责把该点的条目推到眼前

### 选择"updated 排序"而非"时间衰减"

- **放弃**：纯时间驱动的自动降档
- **获得**：与 ADR 0002 "`created`/`updated` 是审计元数据、不参与衰退判断"一致；一条 2 年仍有效的架构依赖不会因"陈旧"被误判
- **代价**：复审名单的优先级需要人看一眼 `updated` 排序，而非自动按年龄触发

### 明确不做

- **时间自动衰减**：违反 ADR 0002。
- **代码扫描/AST 失效判定**（"某模块删除 → architecture 条目自动失效"）：需代码理解，v1.0 已把代码扫描列为 out of scope，且与二分判断哲学冲突。
- **embedding 语义过期检测**：引入模型依赖 + 不可解释，过度工程。
