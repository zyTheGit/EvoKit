# 任务执行流程

## 开发步骤

1. **理解需求** — Read 相关文件，确认变更范围
2. **设计方案** — 复杂任务（>3 步）先列方案，简单任务直接执行
3. **实施变更** — 按方案逐步执行，每步验证
4. **验证结果** — 运行测试，确认无回归
5. **总结记录** — 非显而易见的发现记入 memory

## 需求分析流程

- 收到任务后，先确认：改什么？为什么改？影响范围？
- 不明确时主动提问，不猜测需求
- 将大任务拆分为可独立验证的子任务

## 执行约束

- 每个子任务完成后检查：是否与预期一致
- 遇到阻塞时：报告问题 → 提出方案 → 等待决策
- 不跳过验证步骤，不假设"应该没问题"
