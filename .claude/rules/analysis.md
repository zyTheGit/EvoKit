# 问题分析方法

## 根因定位

1. **复现问题** — 确认确切的错误信息或异常行为
2. **缩小范围** — 找到触发问题的最小输入/操作
3. **形成假设** — 基于代码阅读提出根因假设
4. **验证假设** — 用针对性命令/测试验证，不用 printf 猜测
5. **确认根因** — 修复后用相同复现步骤验证

## 影响评估

- 修改前评估：哪些模块受影响？哪些测试需要更新？
- 使用 `codegraph_impact` 分析依赖链
- 检查是否有其他代码依赖被修改的接口

## 分析原则

- 先读代码再下结论，不凭直觉判断
- 区分"症状"和"根因" — 修复根因而非掩盖症状
- 记录非显而易见的发现到 `observations.jsonl`
