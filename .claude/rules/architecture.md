# 架构设计原则

## 模块划分

- 每个模块单一职责，职责边界清晰
- 模块间通过明确接口通信，不直接访问内部状态
- 新模块遵循现有目录结构和命名惯例

## 扩展性要求

- 面向接口编程，不面向实现编程
- 新功能通过扩展实现，不修改已有核心逻辑（开放-封闭原则）
- 适配器模式：新增 Agent 适配器时实现公共接口，不修改基类

## 依赖管理

- 依赖方向：高层 → 低层，不反向依赖
- 避免循环依赖
- 新增第三方依赖前评估：是否必要？是否有更轻量替代？

## 设计决策

- 简单方案优于巧妙方案
- 匹配现有模式，不引入新模式
- 需求不明确时显式声明假设
